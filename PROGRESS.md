  - **Decision:** (1) upload/transcode pipeline targets ~1.5-2 Mbps 720p as the default encode, keeping total video comfortably under 100GB at this scale; (2) a CDN sits in front of the signed-URL video delivery path (Supabase's own Storage CDN, or a Cloudflare proxy) to cut repeat-egress cost as rewatching grows; (3) video stays on Supabase Storage — no move to a dedicated video host (Mux/Cloudflare Stream) — the existing architecture (signed URLs + server-tracked anti-scrub progress) is built around it, and that migration only earns its complexity if this template gets reused by institutions with a much larger catalog. Archiving completed-course video to cold storage was considered and rejected: Supabase's per-GB storage cost is too cheap for a hot/cold split to be worth the engineering complexity — CDN caching addresses the real cost driver (egress), not storage.
  - **Signed-URL caveat the CDN work must not skip:** lecture URLs are per-request signed tokens (`lib/storage/`), so a CDN that caches on the *full URL* (token included) gets a 0% hit rate — every request looks like a different resource and the CDN adds a hop with no savings. The cache key must be the underlying object path with the token/query string stripped; the signed-URL check still gates whether a request is allowed through before the CDN serves the cached bytes. This is standard for Cloudflare Cache Rules/Workers and dedicated video CDNs, but it's a specific config step, not something that falls out of "just add a CDN" — whoever builds this (`resilience-builder`) needs to verify the cache-hit behavior against a real signed URL, not just that a CDN is present.
